
# Backend для маршрутизатора API

Высокооптимизированный сервер для расчёта и оптимизации маршрутов доставки с поддержкой продвинутых алгоритмов, имитацией дорожных пробок и выбором типа транспорта (автомобиль, велосипед, пешком).

## Быстрый старт

### Запуск через Docker (рекомендуется)

```bash
docker-compose up -d
```

При первом запуске OSRM обработает карту (~1-2 мин). Бэкенд автоматически сгенерирует `traffic.csv` и запустит фоновое обновление каждые 10 минут.

- **API:** http://localhost:8000
- **Swagger UI:** http://localhost:8000/docs

### Локальный запуск (без Docker)

```bash
cd backend
pip install -r requirements.txt
python -m uvicorn main:app --reload
```

## Архитектура и алгоритмы

### Общая схема работы

```
Адреса / координаты
       ↓
  Геокодинг (Nominatim / Photon)
       ↓
  Матрица расстояний / времени (OSRM + traffic.csv)
       ↓
  Оптимизация маршрута (NN → 2-opt → Or-opt → SA)
       ↓
  GeoJSON для фронтенда
```

### Транспортные профили

| Тип | Контейнер | Порт | Профиль OSRM |
|-----|-----------|------|--------------|
| Авто | `osrm-car` | 5000 | driving |
| Велосипед | `osrm-bike` | 5001 | cycling |
| Пешком | `osrm-foot` | 5002 | walking |

### Алгоритмы оптимизации

| Алгоритм | Сложность | Описание |
|----------|-----------|----------|
| **Nearest Neighbor** | O(n²) | Жадный выбор ближайшей точки |
| **2-opt** | O(n²) | Убрать пересечения рёбер |
| **Or-opt** | O(n³) | Перемещение сегментов из 1-3 точек |
| **Simulated Annealing** | O(n²·k) | Выход из локальных минимумов |

## Имитация пробок (traffic)

### Как это работает

Система имитирует дорожные пробки Екатеринбурга с привязкой ко времени суток и дням недели. Пробки влияют на расчёт маршрутов через механизм **segment speed** в OSRM.

```
traffic_patterns.py          ← конфигурация улиц и паттернов
        ↓
traffic_generator.py         ← вычисляет скорости по текущему времени → traffic.csv
        ↓
osrm-customize --segment-speed-file  ← применяет скорости к дорожной сети
        ↓
osrm-routed                  ← маршруты учитывают пробки
```

### Структура паттерна

```python
{
    "name": "ул. Малышева (центр)",
    "from_id": 845815409,       # OSM Node ID начала сегмента
    "to_id": 668987103,         # OSM Node ID конца сегмента
    "base_speed": 40,           # нормальная скорость (км/ч)
    "patterns": [
        {"days": [0,1,2,3,4], "hours": [[8,10],[17,19]], "factor": 0.25},
        #  ↑ пн-пт              ↑ утро + вечер             ↑ 25% от нормы = 10 км/ч
    ]
}
```

- **`days`** — дни недели (0=пн, 6=вс)
- **`hours`** — часы, когда действует паттерн
- **`factor`** — множитель скорости (0.25 = пробка, 0.5 = загрузка, 1.0 = свободно)

### Пример — Малышева, суббота 14:00

| Паттерн | Скорость | Состояние |
|---------|----------|-----------|
| пн-пт 8-10, 17-19 | 10 км/ч | Не действует (суббота) |
| сб-вс 11-16 | 20 км/ч | **Действует** |
| Всё остальное | 40 км/ч | — |

### Жизненный цикл

1. **При старте бэкенда** — генерируется `traffic.csv` с текущими скоростями
2. **osrm-car** применяет `traffic.csv` через `osrm-customize --segment-speed-file`
3. **Каждые 10 минут** — `TrafficUpdater` пересчитывает скорости и перезаписывает `traffic.csv`
4. **Для применения** — перезапуск `osrm-car` (новый `osrm-customize` + restart)

## Примеры запросов

### Оптимизация маршрута (с учётом пробок)

```bash
curl -X POST "http://localhost:8000/route/geojson?mode=optimized&optimize_by=duration" \
  -H "Content-Type: application/json" \
  -d '{
    "points": [
      {"id": 0, "lat": 56.8430, "lon": 60.5970, "city": "Екатеринбург"},
      {"id": 1, "lat": 56.8290, "lon": 60.5970, "city": "Екатеринбург"}
    ]
  }'
```

Маршрут объедет загруженные улицы (Малышева, Ленина), если альтернативный путь быстрее.

### Проверка текущих скоростей

```bash
curl http://localhost:8000/traffic/status
```

### Принудительное обновление traffic.csv

```bash
curl -X POST http://localhost:8000/traffic/update
```

### Геокодинг

```bash
curl -X POST http://localhost:8000/geocode \
  -H "Content-Type: application/json" \
  -d '{"city": "Екатеринбург", "street": "ул. Малышева", "house": "19"}'
```

## Важно

1. **Минимум 2 точки** для маршрута, **максимум 50**
2. **Формат координат:** `lat` (широта), `lon` (долгота)
3. Можно передавать адреса (`city`, `street`, `house`) вместо координат — геокодинг автоматический
4. Если OSRM недоступен — используется евклидово расстояние (haversine)
5. **Пробки работают только для `osrm-car`** — bike и foot не учитывают traffic.csv
6. Часовой пояс системы — UTC+5 (Екатеринбург)

### Фиксированные start / end точки

```json
{
  "start_point": {"lat": 56.8380, "lon": 60.5975},
  "end_point": {"lat": 56.8500, "lon": 60.6100},
  "points": [...]
}
```

Маршрут будет построен с фиксированным стартом и финишем.

## Производительность

| Сценарий | Точек | Время |
|----------|-------|-------|
| Nearest Neighbor | 50 | < 10 мс |
| NN + 2-opt | 50 | < 50 мс |
| NN + 2-opt + Or-opt | 50 | < 200 мс |
| + Simulated Annealing | 50 | < 1 с |

*Основное время — сетевые запросы к OSRM. С кэшем повторные запросы ~мс.*
