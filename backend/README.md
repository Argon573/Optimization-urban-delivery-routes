   ```bash
   pip install -r requirements.txt
   ```

## 🎯 Алгоритмы оптимизации

### **Базовые (всегда включены, в /route/image можно отключать):**
- **Nearest Neighbor** — быстрый алгоритм начального решения
- **2-opt** — итеративное улучшение маршрута (полная оптимизация с учетом всех итераций)

### **Продвинутые (опционально):**
- **Or-opt** — перемещение сегментов из 1-3 точек, дает более качественные маршруты
- **Simulated Annealing** — имитация отжига для выхода из локальных оптимумов

### **Оптимизации производительности:**
- **Векторизованный Haversine** — расчет матрицы расстояний в 50+ раз быстрее через NumPy
- **Кэширование OSRM** — LRU кэш для повторных запросов к OSRM API
- **Оптимизированный 2-opt** — расчет только измененных ребер вместо полного маршрута

### **2. ГЕНЕРАЦИЯ ДАННЫХ**

#### 🔹 **POST /generate** — создать случайные точки в городе

**Запрос:**
```json
POST http://localhost:8000/generate
{
  "city_center": {
    "lat": 55.7558,
    "lon": 37.6176
  },
  "radius_km": 3,
  "points_count": 5
```

**Параметры:**
| Поле | Описание | Ограничения |
|------|----------|-------------|
| `city_center` | Координаты центра города (широта, долгота) | Обязательно |

#### 🔹 **POST /route/image** — GeoJSON маршрута с поддержкой различных алгоритмов

**Параметры запроса:**
- `mode` (string: original, nn, optimized) — тип маршрута:
  - `original` — исходный порядок точек без оптимизации
  - `nn` — только Nearest Neighbor
  - `optimized` — полная оптимизация (по умолчанию)
- `use_advanced` (bool, default=true) — включить Or-opt
- `use_annealing` (bool, default=false) — включить Simulated Annealing

**Запрос:**
```json
POST http://localhost:8000/route/image?mode=optimized&use_advanced=true&use_annealing=false
{
  "points": [
    {"id": 0, "lat": 55.7623, "lon": 37.6245},
    {"id": 1, "lat": 55.7489, "lon": 37.6098},
    {"id": 2, "lat": 55.7591, "lon": 37.6312}
  ]
}
```

**Ответ:** GeoJSON с координатами маршрута (Media Type: application/geo+json)

**Примеры параметров:**
```
# Исходный порядок без оптимизации
/route/image?mode=original

# Только Nearest Neighbor
/route/image?mode=nn

# Полная оптимизация с Or-opt
/route/image?mode=optimized&use_advanced=true&use_annealing=false

# Максимальная оптимизация с Simulated Annealing
/route/image?mode=optimized&use_advanced=true&use_annealing=true

# Быстрая оптимизация (только 2-opt)
/route/image?mode=optimized&use_advanced=false&use_annealing=false
```

## ⚠️ ВАЖНО

1. **Минимум 2 точки** для расчета маршрута
2. **Максимум 50 точек** (чтобы не перегружать OSRM)
3. **Радиус от 1 до 50 км** при генерации
4. **Формат координат:** сначала широта (lat), потом долгота (lon)
5. Можно передавать не только `lat/lon`, но и адрес:
   - `city`, `street`, `house` (опционально),
   - тогда автогенерация координат идет через `/geocode`, а маршруты считают по появившимся `lat/lon`.
6. Если OSRM недоступен, используется прямое расстояние (по прямой)

### 🏁 Начальная и конечная точки

- В `POST /route/baseline` и `POST /route/optimize` можно указать опционально:
  - `start_point` (Point) — точка старта маршрута
  - `end_point` (Point) — точка финиша маршрута
- Если они заданы, то маршрут строится с фиксированным стартом/финишем, а остальные точки вставляются между ними.
- Для `start_point` и `end_point` действуют те же правила: лат/лон либо `city/street/house`.

## ⚡ Производительность и оптимизации

✅ **Векторизованный Haversine** 
- Матрица расстояний считается через NumPy за раз
- Для 100 точек: ~50ms вместо 2-5 секунд

✅ **Оптимизированный 2-opt**
- Расчет только измененных ребер вместо полного маршрута
- Не пересчитывается весь маршрут после каждого улучшения

✅ **Кэширование OSRM запросов**
- LRU кэш (512 записей) для повторных запросов
- Повторная пара точек вернется из кэша за микросекунды
- Идеально для интерактивного режима

✅ **Полная оптимизация 2-opt**
- Гарантирует лучший результат (до локального оптимума)
- Параметр `max_iterations=100` защищает от зависания

### Рекомендации по использованию:

| Ситуация | Параметры | Причина |
|----------|-----------|---------|
| Быстрый результат | `use_advanced=false&use_annealing=false` | Только 2-opt, очень быстро |
| Баланс | `use_advanced=true&use_annealing=false` | Or-opt дает 10-20% улучшение |
| Качество | `use_advanced=true&use_annealing=true` | Максимум, но медленнее (10-50 точек) |
| Real-time UI | `mode=nn` | Только NN, мгновенно |
| GeoJSON на карту | `mode=optimized` | С default параметрами |

## 🔧 Технические детали

### 2-opt алгоритм
```
Пока есть улучшения и < 100 итераций:
  Для каждой пары ребер (i, j):
    Попробовать их развернуть
    Если улучшилось:
      Применить изменение
      Перейти на новую итерацию
```

### Or-opt алгоритм
```
Для каждого размера сегмента (1, 2, 3):
  Для каждой позиции в маршруте:
    Вырезать сегмент
    Пробовать вставить в другие позиции
    Если улучшилось:
      Применить и повторить
```

### Simulated Annealing
```
температура = начальная (100)
Для каждой итерации:
  Сгенерировать соседнее решение (2-opt ход)
  Если оно лучше ИЛИ случайное число < exp(-delta/T):
    Принять его
  Охладить: T *= 0.98
  Если T < 0.0001: выход
```
