# Backend для маршрутизатора API

Высокооптимизированный сервер для расчета и оптимизации маршрутов доставки с поддержкой продвинутых алгоритмов и учётом дорожной ситуации.

## 🔧 Технологический стек

| Компонент | Технология | Назначение |
|-----------|------------|------------|
| **Язык** | Python 3.10+ | Основной язык разработки |
| **Фреймворк** | FastAPI | Создание REST API, автодокументация, валидация |

| **Матрицы** | NumPy | Быстрые матричные вычисления |

| **База данных** | PostgreSQL | Хранение дорожных событий |
| **Контейнеризация** | Docker + Docker Compose | Унифицированный запуск всех сервисов |

## 🧠 Архитектура и алгоритмы

### Общая схема работы

```
Адреса / координаты → Геокодинг → Матрица расстояний → Оптимизация → Оптимальный маршрут
                                    ↓
                          Учёт пробок из БД (штрафы)
```

### Базовые алгоритмы (всегда включены)

| Алгоритм | Сложность | Описание |
|----------|-----------|----------|
| **Nearest Neighbor** | O(n²) | Жадный алгоритм: на каждом шаге идём в ближайшую непосещённую точку |
| **2-opt** | O(n²) | Локальная оптимизация: убирает пересечения рёбер, «выпрямляет» маршрут |

### Продвинутые алгоритмы (опционально)

| Алгоритм | Сложность | Описание |
|----------|-----------|----------|
| **Or-opt** | O(n³) | Перемещает сегменты из 1–3 точек, улучшая локальную структуру маршрута |
| **Simulated Annealing** | O(n²·k) | Имитация отжига — позволяет выходить из локальных минимумов |

### Оптимизации производительности

- **Векторизованный Haversine** — расчёт матрицы расстояний в 50+ раз быстрее через NumPy
- **LRU-кэш OSRM** — повторные запросы к OSRM возвращаются из кэша (512 записей)
- **Оптимизированный 2-opt** — пересчитывается только изменённая часть маршрута

## 🚦 Учёт пробок и дорожных событий

### Как это работает

1. **Сбор данных** — парсер (или демо-функция) собирает информацию о пробках, ДТП и перекрытиях
2. **Хранение** — все события сохраняются в PostgreSQL с TTL 2 часа
3. **Штрафы** — при построении матрицы расстояний для точек, рядом с которыми есть пробка, веса всех рёбер умножаются на коэффициент (зависит от severity)
4. **Оптимизация** — алгоритм `Nearest Neighbor` видит эти точки как «дорогие» и откладывает их посещение на конец

### Влияние severity на штраф

| Уровень пробки (severity) | Штраф (penalty) | Эффект на маршрут |
|--------------------------|-----------------|-------------------|
| 1 (слабая) | ×1.2 | Может стать предпоследней |
| 3 (средняя) | ×1.6 | Смещается к концу |
| 5 (сильная) | ×2.0 | С высокой вероятностью — последняя |

## 📡 Основные эндпоинты

| Метод | URL | Описание |
|-------|-----|----------|
| GET | `/health` | Проверка статуса сервера и доступности OSRM |
| POST | `/geocode` | Геокодинг адреса (адрес → координаты) |
| POST | `/generate` | Генерация случайных точек в радиусе от центра |
| POST | `/route/baseline` | Базовый маршрут (без оптимизации) |
| POST | `/route/optimize` | **Оптимизированный маршрут** (NN + 2-opt + Or‑opt + SA) |
| POST | `/route/image` | GeoJSON маршрута для визуализации на карте |
| POST | `/route/matrix` | Матрица расстояний между точками (для отладки) |
| GET | `/address/photon_suggest` | Автокомплит адресов через Photon (OSM) |
| GET | `/road-events` | Список активных дорожных событий (пробки, ДТП, перекрытия) |

## 🧪 Примеры запросов

### 1. Оптимизация маршрута

```bash
curl -X POST "http://localhost:8000/route/optimize?use_advanced=true&use_annealing=false" \
  -H "Content-Type: application/json" \
  -d '{
    "start_point": {"lat": 55.7512, "lon": 37.6184},
    "end_point": {"lat": 55.7512, "lon": 37.6184},
    "points": [
      {"id": 0, "lat": 55.76, "lon": 37.62},
      {"id": 1, "lat": 55.75, "lon": 37.63},
      {"id": 2, "lat": 55.77, "lon": 37.61}
    ]
  }'
```

### 2. Получение GeoJSON для карты

```bash
curl -X POST "http://localhost:8000/route/image?mode=optimized" \
  -H "Content-Type: application/json" \
  -d '{"points":[{"lat":55.76,"lon":37.62},{"lat":55.75,"lon":37.63},{"lat":55.77,"lon":37.61}]}'
```

### 3. Проверка активных пробок

```bash
curl "http://localhost:8000/road-events?lat=56.8380&lon=60.5975&radius_m=5000"
```

## ⚠️ Важно

1. **Минимум 2 точки** для расчёта маршрута
2. **Максимум 50 точек** (для соблюдения таймаутов OSRM)
3. **Формат координат:** сначала `lat` (широта), потом `lon` (долгота)
4. Можно передавать не только координаты, но и адреса (`city`, `street`, `house`). Система выполнит геокодирование автоматически.
5. Если OSRM недоступен — используется евклидово расстояние (формула гаверсинуса) с пометкой `matrix_source: "euclidean"`.

### Фиксированные start / end точки

Можно задать начальную (`start_point`) и конечную (`end_point`) точки. Маршрут будет построен с фиксированным стартом и финишем, а промежуточные точки оптимизируются между ними.

## 📊 Производительность

| Сценарий | Кол-во точек | Время (≈) |
|----------|--------------|-----------|
| Nearest Neighbor | 50 | < 10 мс |
| NN + 2-opt | 50 | < 50 мс |
| NN + 2-opt + Or-opt | 50 | < 200 мс |
| + Simulated Annealing | 50 | < 1 с |

*Основное время занимают сетевые запросы к OSRM. При использовании кэша повторные запросы выполняются за миллисекунды.*
